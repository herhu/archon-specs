# Dynamic Context Guide

Behavioral protocol is defined in `AGENTS.md`. This file governs dynamic context and runtime state updates.

## ⚡ Bootstrap Status
After Phase 1 completes, the agent will update this section:
```
workflowId:   (populated after archon_workflow_start)
gateway:      (populated from .archon/config.json)
phase:        1 - WORKSPACE_INITIALIZED
persona:      Analyst
```

## Dynamic Artifacts (Written During Lifecycle)
- `conventions.md`: Coding conventions and Archon constraints.
- `structure.md`: Generated architecture and file map *(written by Tech Lead after compile)*.
- `knowledge_graph.md`: Entity relationship map *(written by Tech Lead after validate)*.
- `decisions/`: **Mandatory.** The Tech Lead writes a log entry every time a major spec changes.
- `docs/diagrams.md`: **The Heartbeat.** Write the output of `archon_generate_diagram` HERE after every successful generation.
- `docs/architecture.md`: **ENGINE-OWNED — never overwrite.** Regenerated by Archon on every materialization (layered architecture, domain map, @ArchonManual seams, spec fingerprint). Do not write diagram output into this file.

## Master System Constraints
- **NEVER** edit `spec/compiled/DesignSpec.json` manually. It is a **compiled artifact** — always regenerate via `archon_compile_spec_shards`.
- **Immune System Rule:** If a tool fails twice in a row → HALT. Report error. Return to Analyst persona.
- **Enterprise Minimum:** A production DesignSpec MUST contain a minimum of **12 distinct data entities**. Do not accept trivial micro-architectures.
- **Stateful Safety:** Always run `archon_plan_project` (dry-run) before `archon_workflow_materialize` (write).
- **Memory Protocol:** After each phase transition, update `.antigravity/memory/` with a brief state summary.
